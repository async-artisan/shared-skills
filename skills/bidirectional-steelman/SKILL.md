# 深度决策推演

## 适用边界

用户明确出现上述关键词，或明确要求“先不要回答、先把正反两方想透、找决定性变量”时启用。不要把普通的事实查询、翻译、摘要、机械执行，或用户已经明确要求直接给答案的请求强行改成两轮访谈。

## 两阶段工作方式

把对话分成“分析轮”和“判断轮”。

### 分析轮：先不下最终结论

按以下顺序输出：

1. **真正的问题**：区分用户表面提出的事情、实际想解决的目标，以及相关的约束。用户没有提供的个人事实、数据或动机必须标为“未知/待验证假设”，不得擅自补全后当成事实。
2. **支持方钢人论证**：站在用户当前想法一边，给出完整、最有力、最难反驳的理由。
3. **反对方钢人论证**：公平地构建反方最强版本，不弱化、不讽刺、不把反方写成稻草人。
4. **真正分歧与关键变量**：分开事实、假设和价值偏好，指出最可能改变结论的一个关键变量；必要时再列少量次要变量。
5. **唯一关键问题**：只问一个可独立回答、指向一个信息缺口或决策变量的问题，然后等待用户回答；不要把现金、时间、家庭、市场等多个问题打包成一个复合问句。

分析轮不得提前给出确定性建议。最后只能保留一个问题，不要在标题、列表或结尾追加其他问句。

### 判断轮：用户回答后再裁决

基于新信息重新比较双方论证，给出：

- 明确判断或当前最优选择；
- 关键理由、证据与未验证假设；
- 主要权衡和风险；
- 可执行的下一步；
- 哪个新事实出现时应改变结论。

不要无限追问。如果用户明确要求一次性完成或不希望被反问，则在列出假设和缺失信息后，直接给出带不确定性标注的暂定判断。

## 质量与安全约束

- 钢人不是假装正反双方势均力敌。证据明显偏向一方时如实说明，不为了“平衡”而捏造论据。
- 不把价值选择伪装成事实结论；明确哪些是事实、推断、偏好和风险承受能力。信息不足时可用“事实 / 待验证假设 / 价值偏好”标签，避免混写。
- 优先找真正会改变答案的变量，而不是罗列所有可能因素；避免空泛的“视情况而定”。
- 对医疗、法律、投资、重大财务或人身安全问题，说明不确定性、信息时效和专业意见边界；需要外部事实时先指出应核验的来源，不把缺少实时数据包装成个性化确定性结论；紧急风险优先给出安全行动，不因流程而延误。
- 除非用户要求展示 Prompt 本身，否则直接执行方法，不重复解释这套 Skill。
