# 项目交接

让接手对话获得当前成果、有效决定和明确的第一步，避免重复说明与两边同时修改。提醒、保存、新建接续是不同动作，不互相授权。

## 入口

- **提醒检查**：宿主提示压缩检查点待评估，或准备交付可独立验收的阶段、进入下一大段工作、发现已核实的目标／版本／约束混淆时，按下节评估。收到真实计数或需要登记时，读 [计数、评估与最终核验](references/compaction-reminder.md)。不按聊天轮数或模型感觉估算压缩。
- **仅保存**：用户明确要求保存进度、整理交接，或仅输入 `$project-handoff` 时，读 [保存、自动接续与恢复](references/handoff.md)，执行保存。笼统的“交接一下”不扩展为新建任务。
- **完整交接**：用户明确要求新建并继续，或确认了包含“保存、在指定目录新建并打开、核对后继续”的具体提议时，读同一附页，执行保存与接续；同一次明确授权不逐步重问。
- **恢复／查看**：指定交接来源并要求继续时执行恢复；只要求查看时只读。
- 讨论、审查、修改本 Skill 不执行交接，也不主动提醒。若正好到压缩检查点，记录 `skip` 即可。

## 评估：不能把沉默当作已检查

只用已有任务事实检查，不扫描私人历史，不为评估调用额外模型。

| 条件 | 判断依据 |
| --- | --- |
| 安全位置 | 当前操作已收拢，成果、验证和运行任务归属可定位；用户尚未验收不能写成已验收 |
| 明确后续 | 目标、范围、下一步及完成标准清楚，新对话能确定第一步 |
| 切换收益 | 本次具体收益，例如已结束的探索与后续执行可以分开；不能只说对话太长 |

- 首次到第 3 次自动压缩后，安全且有后续即提醒，不另等大阶段。
- 已有正式提醒后，再提醒须同时满足：新实质阶段、具体收益、距上次正式提醒新增至少 3 次压缩。同阶段改版本、调参、重渲染不算新阶段。
- 新的已核实混淆先纠正，在安全位置可以提前提醒；目标或权限还不清楚时先解决缺项，不能靠换对话绕过问题。
- 纯问答、无后续、讨论本 Skill 不提醒。用户静默与指定节点按下节优先处理。

有计数器时，在检查点最终答复前落下一条结果：

| 结果 | 登记及后续 |
| --- | --- |
| 应提醒 | `prepare`，成功后展示建议；成功准备同时记录本次评估 |
| 暂不适合 | `evaluate --outcome defer`，写明缺项和下次检查时机 |
| 本轮不适用 | `evaluate --outcome skip`，写明纯问答、无后续或讨论本 Skill 等实际原因 |

尚未安全收拢、关键缺项待解决时用 `next_turn`；同阶段无新收益或本轮不适用时用 `next_compaction`，在下一次真实压缩再查。其间出现实质阶段切换或新混淆仍须主动评估。用户指定节点由 `respond defer` 单独登记，Agent 不自行设无限暂缓。`prepare` 被拒绝不能冒充成功评估，应核实拒绝原因并登记合理的暂缓结果。

Hook 能发现到期压缩点没有评估，不能独立识别业务阶段，也不能验证 Agent 写的业务理由是否正确。没有可靠任务标识或 Hook 时，最终答复前自检，不能宣称有程序兜底。

## 展示：最终正文最前，单独一段

本轮决定提醒、用户尚未回应时，将实际建议放在最终答复正文最前、成果列表和任务卡之前，以 **交接建议：** 开头。写明具体原因、接续第一步和确认覆盖的动作，不放进引用、示例或代码块。例句只作格式示范，不能据此认定项目事实：

> 交接建议：资料筛选已完成，后续进入方案编写，适合只带入已选资料与约束。确认后我会保存材料，在同一项目原目录新建并打开任务，核对后继续编写方案。

进度消息不替代最终展示。只有宿主结束事件中的最终文本通过核验才记正式提醒，并开始提醒冷却；文本核验不等于用户已经看到。用户已回应、建议撤销或任务已无后续时，不继续保留待决定建议。已交付的建议不在以后每轮重贴。

漏评估与漏最终建议共享每轮最多一次补漏机会。补漏仍失败则留下未核验状态，不循环、不虚报成功；异常不能阻止原任务正常推进。计数器记录是提醒状态，不是业务交接材料。

## 去重与用户回应

- 同阶段、同一具体混淆只提醒一次。后续压缩检查可以得出暂不提醒，不能仅因冷却结束就再次催促。
- 明确回应“先不交接／继续做”后，从回应时再冷却至少 3 次压缩；重复读取同一回应不延长冷却。普通工作指令里的“继续”不自动当作回应或交接批准。
- “做完 X 再提醒”以指定节点为准，到节点评估，不另加次数门槛。新混淆可提前评估；同一问题去重。
- “本任务不提醒”关闭本任务主动提醒和自动评估补漏，直到用户主动恢复；显式交接请求仍执行。
- 用户未回应时继续已授权工作，不追问、不自动保存或新建任务。没有相应工具时只承诺实际可执行的手动入口。

规则仅放在本 Skill 与配套资源；不写入全局路由、不添加定时任务、不修改压缩阈值。保存和接续仍按既有授权及宿主边界执行。
